## Available labs

**Material Lab** (`labs/materials/`) is a Blender-style Shader Editor in English with the full Principled BSDF (Subsurface, Specular, Transmission, Coat, Sheen, Emission, Thin Film), a live PBR preview and a Properties editor (Render Engine EEVEE/Cycles, Raytracing, the Compositor Glare node, Subdivision Surface with Adaptive Subdivision, the Displace modifier, Material Settings › Displacement and Raytraced Transmission). Seven stages: nodes and mapping; metal or not; maps and colour spaces (with alpha cut-outs); relief (Bump, the Displacement setting, enough vertices, the Displace modifier); light and glass (Emission, Glare in the Compositor, emission lighting, glass in Cycles and in EEVEE); layers of the Principled (car paint, velvet, skin and wax, soap bubble, brushed metal); and a Studio with presets. The preview can use the Lighting Lab's HDRIs.

**UV Unwrap Lab** (`labs/uv-unwrapping/`) copies Blender's UV Editing workspace: a UV Editor and a 3D Viewport side by side, an Edit Mode header with Edge/Face Select, Select and UV menus, and a status bar that shows the available keys. Students select edges (Shift to add), then Mark Seam through the U menu, Ctrl+E, the right-click menu or the header buttons, and Unwrap. Live Unwrap (on by default) updates the map immediately; turned off, the map is marked out of date until students run Unwrap, as in Blender. Hovering an edge highlights it in both views, and a seam appears twice in the UV map. Face Select + Mark Seam cuts around the selected faces. Tab switches Object/Edit Mode (the UV Editor only shows UVs in Edit Mode). A "Quick Seam" tool is a clearly labelled lab shortcut that toggles a seam with one click. The 3D faces sample a texture painted from the UV map with a UV-space checker, so stretch and uneven density are visible on the model. Unfold works for the cube and the chair: every face hinges about its shared edge and lands exactly on its UV position. Object Mode has a Transform panel, S to scale and Ctrl+A › Scale to apply; an unapplied non-uniform scale reproduces Blender's unwrap warning and a stretched checker until the scale is applied and the object unwrapped again. Closed loops and overlaps are explained rather than silently shown.

**Code Lab** (`labs/csharp/`) teaches programming fundamentals in C#. Students program a drone that builds voxel sculptures on an 8 × 8 grid and compare the result with a ghost target. A small interpreter written for the lab runs a subset of C# step by step: the next line is highlighted, conditions are shown as they are evaluated (`i < 7 → 3 < 7 → true`), a Memory panel shows each variable with its type and scope, gutter counters show how many times each line ran, and inline notes show what each line did. Before running, a checker reports compiler errors with real C# codes and messages (CS1002, CS0029, CS0103…) plus a plain-English hint. Runtime errors (leaving the grid, dividing by zero, endless loops) stop the program at the line that caused them. There are 70 challenges in 13 levels. The course starts without any statements or method calls: a **Calculator** mode (like C# Interactive: one calculation per line, no semicolons, each result shown next to its line with its type, and optionally built as a tower) introduces operators, precedence, integer division, `%` and value types; **Names** covers case-sensitivity, valid identifiers and camelCase/PascalCase with Classify challenges judged by the real checker, plus first variables; **Text** shows every string as a strip of characters with their positions (0, 1, 2…) and highlights what `[i]`, `Length`, `Substring` and `IndexOf` touch, with `char`, string methods and interpolation; **Logic** lights a lamp for every true/false answer and shows how each condition is worked out step by step (`age >= 18 && member → 16 >= 18 && true → false && true → false`), the same step-by-step evaluation used later by `if` and loops. Then come first instructions (`;`, `Console.WriteLine`, method calls), the drone, variables and types, loops (for, nested, while), conditions (if/else, %, &&, ||), **methods** and a sandbox. Methods are written below the main program as local functions (`void Tower(int h) { … }`, `int Area(int w, int d) { return w * d; }`); the Memory panel shows the call stack with one frame per call, Step (F10) runs a call in one go and Step Into (F11) follows the program inside, and the Execution panel shows the value each call gives back. **Arrays** (`int[]`, `Color[]`, `{ … }`, `new int[n]`, `Length`, `foreach`) are drawn in Memory as a row of boxes with their positions, lighting up the box read or written in each step; going one position too far stops with an IndexOutOfRangeException that names the position. The final project, **From block to city**, uses `drone.Scan()` (the plan of the current row as an `int[]`, different on every run) to generate streets, a whole city and a terrain from a heightmap. Challenges come in seven types, following how beginners learn best (read before write, PRIMM): **Observe** (read-only, follow with Step), **Predict** (choose an answer before running; the answer is checked against what really happens), **Order** (Parsons problems: drag the shuffled lines into order, with distractors; braces indent automatically), **Fix** (compiler and logic errors), **Complete** (fill the `___` gaps), **Classify** (choose a category for each item; the compiler or a naming rule decides) and **Create**. Some challenges check the Console output instead of, or as well as, the shape. `drone.Build(n)` turns numbers into towers (with height labels) and the drone shows the last Console line in a speech bubble. Two challenges randomize the starting world and are verified on other worlds, so hard-coded answers fail. Progress and code are saved in the browser. Shortcuts follow Visual Studio: F5 Run/Continue, F10 Step (over a method call), F11 Step Into, Shift+F5 Stop; click a line number for a breakpoint.

**Code Lab 02** (`labs/csharp-objects/`) continues the Code Lab towards Unity with the same app and interpreter (the page sets `data-course="objects"` and loads `labs/csharp/levels-objects.js`). The interpreter adds classes and structs (fields, public/private/protected, constructors with `: base(…)`, instance methods, `this`, virtual/override with real dispatch rules), `new`, `null`, reference semantics, `List<T>` (Add, Remove, RemoveAt, Insert, Contains, IndexOf, Count, indexer, collection initializers, modification during foreach), and a Unity-like layer: `Vector3` as a struct (operators, `normalized`, `magnitude`, `Vector3.up`…), `MonoBehaviour` with `transform.position`, `Time.deltaTime`, `Mathf`, `Debug.Log` and `Scene.Add`, after which the lab calls `Start()` once and `Update()` every frame and draws each object (with a dot per frame). Real compiler errors teach the classic mistakes: CS0122 (private fields), CS1612 (changing `transform.position.y`), CS0037, CS1729, CS0506/CS0115, CS0108/CS0114 warnings, CS8803 (classes must come after the main program), plus NullReferenceException and InvalidOperationException at runtime. The Memory panel shows variables of a class as arrows (→ #3) to objects in a **heap**, structs inline, and objects nothing points to any more faded out. 30 challenges in 7 levels: classes and objects, references and null, lists, structs and Vector3, Update and time (from moving objects to the bouncing ball simulated in code), inheritance, and ready for Unity.

**Animation Lab** (`labs/animation/`) teaches the bouncing ball in four stages with a Blender-style workspace.

The workspace has three editors:
- **3D Viewport** (Three.js, Pose Mode) with a rigged ball. The rig follows the one used in class: a **Root** control at the base, two squash & stretch controls and a **Rotation** control. **SS_Top** moves the top of the ball (pivot at the base, for the contacts) and **SS_Bottom** moves the bottom (pivot at the top, to stretch towards the floor). The rig keeps the volume. Controls are selected with LMB and moved with G (only up and down, with typed values). I inserts a keyframe and Alt G clears. As in Blender, an unkeyed pose is discarded when the frame changes. The viewport also shows Motion Path dots, optional ghosts and a 1 m grid wall.
- **Graph Editor** with a channel list grouped by bone and a sidebar (Active Keyframe, bounce heights and frame counts, rig values, lowest point). F-curves behave like Blender's: Constant, Linear and Bezier interpolation, and Free, Aligned, Vector, Automatic and Auto Clamped handles (automatic handles become Aligned when dragged).
- **Timeline** where keyframes can be edited too. Drag the numbers to change frame. Click a keyframe to select it (Shift adds), drag it or press G to move it in time, drag on empty space to box-select, and press X to delete.

Keys go to the editor under the mouse.

The four stages:
- **Timing**: ease in and out, sharp contacts with Vector handles, lower bounces, shorter bounces.
- **Squash & Stretch**: squash with SS_Top at the contacts, stretch down with SS_Bottom before the contact and up with SS_Top after it, round at the tops, and never through the floor.
- **Weight**: a bowling ball, a beach ball with hang time, and a match with a physically simulated bounce.
- **Rotation**: a Rotation control (R to turn it, typed degrees, Alt R) turns the ball inside its squash, so the squash stays vertical. Roll the right way and the right amount (360° every π × diameter of travel), make the rotation follow a constant travel (Linear), and slow it down with an eased travel.

The **Controls** switch in the 3D Viewport header hides the rig controls (as Overlays › Bones in Blender) to judge the motion on the ball alone.

Each step is checked automatically, can show a solution and can be undone.

**Skin Weights Lab** (`labs/skin-weights/`) is a Blender-style Weight Paint workspace for practising skinning. A 3D Viewport (Three.js) shows a tube-shaped arm, or a pair of arms with a chest, with octahedral bones drawn in front. The mesh is deformed with linear blend skinning, like Blender's Armature modifier, and coloured with Blender's weight ramp (blue 0 → red 1) for the active vertex group. The tool header has Blend (Mix, Add, Subtract), Weight, Radius, Strength, Auto Normalize, X-Mirror (which paints the .L/.R group with the opposite name on the mirrored vertex) and Front-Face Only. The toolbar has Draw, Blur and Sample Weight. The overlays offer Zero Weights (None/Active/All), Wireframe and Rest Position. The Weights menu has Assign Automatic from Bones, Normalize All, Mirror, Clean, Limit Total and Smooth, with an Adjust Last Operation panel (Subset, Limit, Factor, Iterations) that re-runs the operator. There is also a Parent menu (Ctrl P: With Empty Groups, With Automatic Weights). The properties show the Vertex Groups list, a Pose panel (Bend and Twist per bone, R to rotate with the mouse, Alt R to clear), the weights and total of the vertex under the cursor, and a Checks panel (zero weights, not normalized, max influences, tiny weights, symmetry error). The lab has four stages: **Automatic weights** (a mesh that does not follow its bones, parenting With Automatic Weights, reading the gradient, the candy-wrapper effect of a twist), **Fix the elbow** (blur a hard edge into a gradient, blurring both groups with Auto Normalize, then normalize), **Find the problems** (a zero-weight patch, a stray .L weight on the .R side, a hard elbow fixed by mirroring) and **Game ready** (Limit Total 2, Clean below 0.05, Normalize All before export). Steps are checked automatically and each has a solution and undo. Ctrl-click a bone to select its group; MMB orbits, Shift MMB pans, Alt LMB also orbits, and Numpad 1/3/7 and Home set the view.

**Rig Lab** (`labs/rig/`) is a Blender-style Pose Mode for learning FK and IK. A 3D Viewport (Three.js) shows an armature with octahedral bones drawn in front, custom shapes for the controls, rigid pieces of mesh, relationship lines, the IK line and the pole line. Bones are selected with LMB (Shift to add; the last one is active), rotated with R and moved with G. After R or G, X/Y/Z constrain to a global axis and pressing it twice to the bone's own axis; typed numbers give exact values; click or Enter confirms and Esc cancels. Alt R and Alt G clear the pose, and connected bones can only rotate. The properties show a bone list, a Transform panel (location and XYZ Euler rotation in the bone's own axes, editable), Bone Constraints and a readout. The IK constraint is added from Add Bone Constraint or with Shift I › To Active Bone. It has Bone (target), Pole Target, Pole Angle, Chain Length and Influence, and the lab solves it exactly for two bones: the root's X axis is turned towards the pole plus the Pole Angle, as Blender does. There are two stages. **Forward kinematics** (arm): parents move their children, copy a ghost pose from the root to the tip, and keep the fingertips on a cup after twisting the chest. **Inverse kinematics** (leg): add the IK with Chain Length 2 (0 also rotates the Hips), fix a straight leg whose knee bends backwards with a Pole Target and Pole Angle -90°, crouch with the foot planted and steer the knee with the pole, and use Influence as an IK/FK switch. Steps are checked automatically and each has a solution and undo.

**Photo Lab** (`labs/photo/`) teaches how a camera works. On the left is a DSLR cut in half (Three.js, orbitable, with labels). Its lens gets longer with the focal length, the 7-blade iris closes with the f-number and the sensor changes size. **Shoot** (Space) plays the real sequence: the mirror flips up, the aperture stops down, the first curtain opens, the second closes and the mirror comes back, with the light path to the viewfinder or to the sensor. Exposures shorter than 0.4 s are shown slowed down. On the right is the photo, rendered with a physical camera. Depth of field, bokeh, motion blur and camera shake come from averaging up to 40 renders, each from another point of the aperture and another instant of the exposure (off-axis frustums, like an accumulation buffer or Cycles). Exposure error and ISO noise are applied at the end, with a histogram, a viewfinder line and a meter from −3 to +3. Click the photo to focus. The settings panel has M / Av / Tv modes, full-stop aperture, shutter and ISO, focal length (16–200 mm), focus, distance, sensor (full frame, APS-C, Micro Four Thirds) and a tripod, plus a live readout: exposure, depth of field, background blur, motion blur, shake, hand-held limit, framing, angle of view and equivalent focal length. There are three stages. **Exposure triangle**: balance the meter, blur the background, freeze a cyclist, show the movement on a tripod, low light by hand. **Focal length & sensor**: frame the person, perspective compression (same framing at 24 mm and 135 mm), crop factor. **Blender camera**: a Blender-style Camera / Render / Output properties panel (Focal Length, Sensor Fit, Size, Depth of Field with Focus Distance and F-Stop, Motion Blur Shutter in frames, Frame Rate), where students match a reference render.

**Baking Lab** (`labs/baking/`) teaches baking from a high poly to a low poly. The model is a crate: Crate_high has 110,592 triangles (bevels, bolts, grooves, slots and a striped plate), Crate_low is a cube of 12 triangles with one UV island per face. The workspace has a 3D Viewport (the low poly with the baked maps, the high poly, the cage and a sample of the rays: green = hit, yellow = wrong hit, red = miss), an Image Editor (the baked image filling up row by row, R/G/B channels, UV overlay, misses, and a texel inspector that decodes the normal and draws its ray in 3D) and a Properties column (Outliner with selection and active object, shading and UV map of Crate_low, a Blender-style Bake panel, the material and an engine preview). Baking runs in the browser with a small ray caster (BVH, Möller–Trumbore), in slices with a progress bar (Esc cancels). There are three stages. **Normal map**: Selected to Active, Extrusion to reach the bolts, a Cage to close the corners of a low poly with hard edges. **Tangent space**: read the colours of the map, OpenGL vs DirectX (Swizzle G −Y or Flip Green Channel for Unreal), no overlapping UVs. **Maps & engine**: Ambient Occlusion with enough samples, Diffuse with only Color, connect the maps (Non-Color, Normal Map node, AO multiply) and Margin against mipmap seams. **Substance Painter**: the same crate with a steel handle, in a Painter-style Baking window and Export Textures panel. Max Frontal / Rear Distance (Relative to Bounding Box), Average Normals or Use Cage, Match By Mesh Name (_low / _high) so the handle is not baked into the crate, the mesh maps for smart materials (World Space Normal, ID, Ambient Occlusion, Curvature, Position, Thickness) with a small smart material preview, and output templates (Blender, Unity, Unreal Engine (Packed)) with the OpenGL / DirectX normal map of each engine.

**Lighting Lab** (`labs/lighting/`) teaches lighting with a plaster bust, a grey ball and a chrome ball in front of a paper backdrop. The 3D Viewport (perspective or top view) shows the lights as Blender-like gizmos: drag them around the bust (Azimuth, Elevation) and use the wheel for Distance. They always point at their target, like a Track To constraint. The Render is progressive: every sample moves each light over its emitting surface (Radius, Size, Angle) for real soft shadows, and the average goes through Color Management (Exposure; Standard, AgX or False Color). The Properties column has an Outliner (Key, Fill, Rim, BG lights and a bounce card), Blender-style Light panels (Point, Sun, Spot, Area, Power or Strength, Blackbody temperature, Spot Size and Blend, Shape and Size), World (colour or three procedural HDRIs with Rotation and Strength), the backdrop colour and a light meter. The physics lives in `light.js` (no DOM): inverse square law, cosine, spots, area lights, the bounce card, HDRI irradiance and blackbody colours. The step checks read that meter. There are five stages. **Types of light**: twice as far, the Sun does not fall off, a spot on the face, an Area light. **Hard and soft**: bigger is softer, farther is harder, match a reference image. **Classic setups**: three-point, Rembrandt, butterfly, split and low key, high key. **Colour and world**: warm and cool, light with an HDRI, a bounce card. **Exposure and view**: Exposure, Standard or AgX, reading with False Color.

**Topology Lab** (`labs/topology/`) teaches mesh topology in a Blender-style Edit Mode on small meshes. It has vertex, edge and face select modes, click and Shift-click selection, Alt-click edge loops, A / Alt A, Move (G with X / Y / Z), Loop Cut and Slide (Ctrl R, with a live preview of the ring), Connect Vertex Path (J), Dissolve Vertices and Edges (X), Fill (F), Tris to Quads (Alt J), Edge Crease (Shift E), Smooth Vertices, Subdivision Surface (Ctrl 0–3) and snapping to a high poly. Face-type and pole overlays and a Statistics panel read the mesh. The mesh core (`mesh.js`, no DOM) has edge rings and loops, connect, dissolve, fill, and Catmull-Clark subdivision with creases. There are four stages. **Read the mesh**: no n-gons, triangles into quads, find the poles of a bottle cap. **Subdivision Surface**: pinches, holding edges (corner loss under 12%), crease instead of loops. **Deformation**: loops at the elbow of an armature-bent arm, slide the loops to where it bends, Preserve Volume (linear blending vs dual quaternions). **Retopology**: fill the holes of a quad cage on a sculpted stone, snap it to the surface, even out its density.

**Tileable Texture Lab** (`labs/tileable/`) explains tileable (seamless) textures with two workspaces. Blender stages use a Blender-style Image/UV Editor, a 3D Viewport with a custom shader (Mapping scale, Extension Repeat/Extend/Clip/Mirror, UV or Object coordinates, Flat or Box projection with Blend, per-map offsets, a Noise Texture multiplied over the colour and a second texture mixed through a noise mask) and a Properties panel drawn as shader nodes. Photoshop stages use a Photoshop-style workspace: menus (Image › Image Size, Adjustments › Desaturate/Invert, Layer › Duplicate/Flatten, Filter › Blur › Gaussian Blur, Filter › Other › Offset with Set to Background / Repeat Edge Pixels / Wrap Around, View › Pattern Preview), a toolbar (Crop with 1:1 ratio, Clone Stamp and Healing Brush with Alt-click source, size, hardness and Aligned, Hand, Zoom), a Layers panel with blend modes and opacity, and a lab check panel. `texture.js` paints the procedural photo and textures (gravel, bricks, rock, moss) and holds the image operations and measurements (seam ratio along a line, light unevenness, pebble structure, chroma, stain ratio); `bank.js` builds every image the steps start from; `walls.js` holds the UV islands of a small building. Seven stages: **Use it** (spot the seam of a non-tileable photo on a floor, Extension Repeat and Mapping scale at real size); **UVs for tiling** (islands outside 0–1 at 2 m per tile, straight and not stretched, the pattern round the corners); **Prepare the photo** (square power-of-two crop and Image Size without stretching or upscaling, even out the light with a desaturated, blurred, inverted copy in Linear Light at 50 %); **Make it seamless** (Offset with Wrap Around, Clone Stamp and Healing Brush over the cross with a seam check, Pattern Preview and a stain that gives the repetition away); **PBR maps** (a Roughness map that does not tile, maps offset differently); **Scale & projection** (texel density from image size and metres per copy, Box projection on a rock without good UVs); **Break the repetition** (large noise variation, a second texture whose size is not a multiple of the first, with the distance at which both line up again). Photoshop steps keep their pixels for the visit only; Blender steps are saved in the browser.

**Trim Sheet Lab** (`labs/trim-sheet/`) explains trim sheets with a procedural medieval sheet (wood planks, stone course, wood beam, stone molding, iron strap, stone plinth, wood and stone bevels; 1024 px at 512 px/m, 8 px padding). A Blender-style UV Editor (the sheet repeating along U, strip names, island selection in 2D or on the model, G / S / R with X / Y, Ctrl snapping, typed values, Pivot, Follow Active Quads, Align Rotation) sits next to a live 3D view of a wall, a column, a chest and a chamfered beam. A side panel reads each island: texel density, strip, straight, upright, not stretched. Five stages: **Read a trim sheet** (which strip is which; only U repeats); **Design the sheet** (heights from texel density, fill 1024 px, padding for mipmaps with a mip preview); **UVs to the strips** (fit a beam, stack and stagger stone rows, straighten a column with Follow Active Quads, equal texel density); **Bevels with trims** (chamfers on a bevel strip, Flat / Smooth / Smooth by Angle / Weighted Normal, chamfer width equal to the strip height); **One sheet, many props** (Fit to Trim, re-skinning every prop with another version of the sheet).

**Stage House Lab** (`labs/stage/`) explains the stage house of an opera house with a 3D model cut in half, simplified from the Teatro Real in Madrid (14 × 11 m opening, grid at 32 m, wings, rear stage, 24 m understage, six platforms of 18.2 × 3.5 m, orchestra pit lift, safety curtain, fly galleries). A seat view shows what four seats see (front row, far left, far right, top balcony), with red points on what should be hidden, and sightlines through the opening. Every piece moves along its own track with G, typed values or the list; interlocks stop a wagon at a lowered platform, at a backdrop or at another wagon. Five stages: **The stage house** (find 12 parts; fly a 12 m backdrop out of sight, which is why the tower is tall; lower the pit for opera); **Upper machinery** (balance a counterweight set brick by brick; share a 1100 kg truss between bars of 750 kg); **Lower machinery** (stepped platforms, sink a statue, bring on a wagon over the platforms); **Masking** (legs against the side seats, borders against the front row); **Scene change** (forest → palace → hell in the right order).

**Color & Type Lab** (`labs/color-type/`) teaches colour and typography for interactive graphic products with a Figma-style editor (Layers, Design panel with Fill / HSL / Text / Contrast, colour styles with Light and Dark modes, text styles) on the home page of a film festival. Six open fonts are included (Inter, Jost, Merriweather, Playfair Display, Lobster, JetBrains Mono) with metrics measured from the files. Colour maths in `color.js`: HSL, WCAG 2 contrast (AA/AAA, large text, 3:1 non-text), CIEDE2000, colour vision deficiency (Machado 2009, also as SVG filters for the preview) and a teaching model of offset printing (Yule-Nielsen Neugebauer with FOGRA39-like primaries) for proof colours, gamut warnings, rich black and total ink. Four stages: **Colour on screen** (mix a colour by HSL, readable greys, a button that passes text and non-text contrast, not only colour); **Screen and print** (light and ink, out of gamut, black ink and rich black within 300%); **Typography** (anatomy lines and x-height, comfortable body text by size, line height and characters per line, text faces, tracking and capitals); **Hierarchy and system** (a modular type scale, two families, colour styles with contrast pairs, dark mode).

**Stage Lighting Lab** (`labs/stage-lighting/`) is a small theatre stage (12 × 8 m, cyclorama, black masking, FOH and two overhead bars) with a rig of twelve fixtures driven like a DMX lighting desk such as Lightkey: fixture list, 3D view with real spotlights, haze beams and an audience preview, an Inspector (dimmer, gel, zoom, edge, LED mixing, pan and tilt, colour wheel), a live DMX monitor of the universe and a cue list with Record, fade times and GO. `rig.js` holds the photometry (candela, inverse square law, cosine, beam falloff, zoom), the DMX footprints and 16-bit pan/tilt, the patch checks, DIP switches, gels and LED mixing, and cue blending. Four stages: **The fixtures** (profile, Fresnel, PC, LED PAR and moving head; hard special and soft wash); **DMX and patch** (typing DMX values, a patch without overlaps, DIP switches); **Designing the light** (face in lux with key/fill and backlight, warm and cold, aiming a moving head); **Cues** (record the preset and the scene, fades, blackout and GO).

**Texel Density Lab** (`labs/texel-density/`) explains texel density (texture pixels per metre) with a Blender-style UV Editor over a checker grid, a 3D view whose textures are painted procedurally at their real resolution, and a Texel Density panel like the Texel Density Checker add-on. `td.js` holds the props (crate, wall, barrel, cabinet, vending machine), the density maths, Average Islands Scale, Pack Islands, Set TD, overlap checks, screen density and texture memory. Five stages: **See it** (checker map, blurry next to sharp); **Measure it** (px ÷ m, the three knobs: texture, UVs, object scale); **Match it** (S by hand, Average + Pack, one density for the scene with the smallest textures); **Choose it** (the target from the camera with a pixel loupe, texture sizes in a memory budget); **Break the rule** (hero front, hidden back, when to break it).

**LOD & Mipmaps Lab** (`labs/lod/`) explains levels of detail and mipmaps. `lod.js` builds a lumpy rock as a geodesic sphere of frequency n (20·n² triangles), measures the error of each LOD against LOD0 in metres and on a 1080p screen in pixels, and holds the LOD Group logic (thresholds in % of screen height, LOD Bias, Culled), the minimum Decimate ratio for a distance, mip levels and memory, and a field of 160 rocks. The 3D view shows the rock at any distance with LOD colours, a dithered Cross Fade and two insets rendered at the real pixels of a 1080p screen (LOD0 next to the LOD in use). Four stages: **What a LOD is** (see LOD0–LOD3, set thresholds so each LOD appears with 0.5–1 px of error, hide the pop with Cross Fade); **Make the LODs** (Decimate Collapse Ratio and Face Count, the smallest ratio for 8 / 20 / 50 m, Collapse vs Un-Subdivide vs Planar); **Mipmaps** (a real GPU floor that shimmers without mips, the mip colours view and log₂(texels per pixel), Bilinear / Trilinear / Anisotropic, +⅓ memory); **Scene budget** (LOD Group, LOD Bias and Culled on a field of rocks within 1.1 million triangles).

**Color Grading Lab** (`labs/grading/`) teaches colour grading for video in a DaVinci Resolve-style Color page: a viewer (Bypass, Split with a Gallery still, Highlight), a Node Editor with serial nodes, palettes (Color Wheels with Lift / Gamma / Gain / Offset pucks and master dials, Temp, Tint, Contrast, Pivot, Sat, Hue; a Custom curve; an HSL Qualifier with picker; a Circle Power Window; LUTs) and scopes (Waveform, Parade, Vectorscope with skin tone line, Histogram). `shots.js` paints three shots (interview A camera, interview B close-up, exterior) as a flat log-like camera would record them, with region masks; `grade.js` holds the grade maths and the measurements. Five stages: **Read the scopes**; **Primary correction** (blacks and whites, a neutral grey card, saturation); **Nodes and the look** (a LUT on a serial node, an S curve); **Secondaries** (qualify the sky, light the face with a window); **Shot matching** (B camera against a still of the A camera, colourist decisions).

**Lightmap Lab** (`labs/lightmaps/`) teaches lightmapping for Unity 6 (URP) with Blender. `lightmap.js` holds a small room made of rectangles and boxes (window, pillar, crate, vase, door), a shelf-packed lightmap atlas (Lightmap Resolution × Scale In Lightmap, padding, Max Lightmap Size), a progressive path tracer run in slices (sun, sky with Environment Samples, bounces with Indirect Samples, Gaussian or denoiser filtering of the indirect light, dilation into the padding, Baked vs Mixed · Baked Indirect), light probes (L0 irradiance, blended nearest probes, Adaptive Probe Volumes as a grid) and the Blender FBX / Unity import checks. The scene view draws lightmaps with a shader that adds the real-time sun with analytic shadows (boxes and the character), a Baked Lightmap and a UV Charts mode; a metal ball uses a captured cube map with box projection. Four stages: **UV2 and export** (UV0 overlaps, Lightmap Pack margin in texels, FBX and Model import settings); **Bake in Unity** (resolution, Scale In Lightmap, bounces, samples and denoiser); **Light modes** (Baked vs Mixed with a walking character, static flags and Receive GI, Lighting Mode quiz); **Probes** (Light Probe Group placement on a top view, APV spacing, Reflection Probe with Box Projection).

**Viewport Lab** (`labs/viewport/`) is the first hour in Blender: a Layout workspace with a 3D Viewport in Object Mode, an Outliner and a sidebar (N) with Location, Rotation, Scale and Dimensions as Blender-style number fields. `vp.js` (no DOM) holds a turntable view with Blender's axis views and Auto Perspective, projection and picking rays, Blender XYZ Euler rotations, the modal transforms (G/R/S, X/Y/Z, Shift + axis to lock, pressing twice for local, typed values, Ctrl snapping, Shift precision) and the Shift-click selection rules. Navigation: MMB orbit, Shift MMB pan, wheel and Ctrl MMB zoom, Alt + LMB (as Emulate 3 Button Mouse), a navigation gizmo that orbits, pans and zooms, Numpad views with an Emulate Numpad switch, the ` pie menu, View › Viewpoint, Numpad . and Home. Selection has click, Shift-click, B and drag boxes, A, Alt A, Ctrl I and an orange outline (lighter for the active object). Edit › Undo History, Add (Shift A), Duplicate (Shift D), Delete (X) and Object › Clear (Alt G/R/S) complete it. Four stages: **Look around** (find three marks by orbiting, pan and zoom to a far sphere, frame the Cone and frame all, Front/Right/Top/Back in order); **Select and transform** (three spheres with the right active object, move cubes to silhouettes with an axis-only move, exact values G Z 2 / R Z 45 / S 1.5); **Cancel, undo, challenge** (cancel a transform, undo three steps of history, four silhouettes with no hints); and a **Free mode**. Based on the Blender labs by Joan Copla (https://joancopla.github.io/blender-lab/), reimplemented and adapted to Carrot Revolt Labs.

**Edit Mode Lab** (`labs/editmode/`) continues it in Edit Mode. `em.js` (no DOM) is a polygon mesh editor: selection flushing between vertices, edges and faces, edge loops, edge rings and face loops, Loop Cut and Slide with several cuts and a slide factor, Extrude Region, Inset Faces, Bevel on separate box-like edges (Width, Segments), Merge by Distance and At Center, Delete and Dissolve (vertices, edges, faces), occlusion tests for selection without X-ray, and a mesh analyser (duplicated and loose vertices, vertices in the middle of an edge, open edges, edges with three or more faces, winding and volume). The workspace has Tab, the 1/2/3 select modes, X-ray (Alt Z), click, Shift-click, Alt-click and boxes, G/R/S on the selection (the same modal code as the Viewport Lab), E, I, Ctrl R, Ctrl B, M and X menus, the Statistics overlay, the sidebar Median and an Adjust Last Operation panel that re-runs Inset, Bevel, Loop Cut, Extrude and Merge with new values. Blue dashed wireframes show the goal shapes. Four stages: **Select in Edit Mode** (marks in each select mode, the +X half with X-ray, two edge loops of a sphere); **Shape the mesh** (truncated pyramid, an L with Extrude, an open box with Inset and a negative extrude, a barrel with loop cuts, a rounded box with Bevel); **Clean and build** (repair a cube with duplicated vertices, a vertex on an edge, a split face, a hidden face and a loose vertex; model a stool, checked with horizontal slices for four separate legs and a clean mesh); and a **Free mode**. Also based on Joan Copla's labs.

The Blender labs follow Blender conventions where it helps transfer: Material Lab links are made by dragging from an output to an input (compatible inputs light up), removed or moved by dragging a connected input away, and cut with Ctrl + right-drag; the mouse wheel zooms, the middle button pans and Home fits all nodes; values use Blender-style slider bars.

**Languages.** Every page has an EN / CA / ES switch in the header. The explanations, instructions, feedback and hints are translated into Catalan and Spanish; the interface names and technical terms (Blender's Mark Seam, UV Editor, Principled BSDF…, C# keywords and code) stay in English so they match the real software, and real C# compiler messages (with their CS codes) stay in English with a translated hint. The choice is saved in the browser; the first visit follows the browser language. The shared engine is `i18n.js`; each page has its own dictionary (`home.i18n.js`, `labs/<name>/i18n.js`) whose keys are the English texts, with `{placeholders}` for changing values.

Open a lab from the home page. To add another lab later, create a new `labs/<name>/` folder with its own `index.html` and add its card to the root `index.html`. The root page, existing lab and shared `vendor/` library can then remain in place.

## Material Lab scope and accuracy

This is a teaching simulation, not Blender running in a browser. It uses Three.js's physical material renderer, so results may differ from Blender's render engines. It cannot load `.blend` files or evaluate arbitrary Blender graphs. The interface uses English to match Blender; explanations can be switched to Catalan or Spanish.

Texture Coordinate includes Generated, Normal, UV, Object, Camera, Window and Reflection. Mapping includes Point, Texture, Vector and Normal modes, with Vector, Location, Rotation and Scale in XYZ. All seven coordinate outputs can feed Mapping or an Image Texture directly. Mapping's Location, Rotation and Scale sockets can receive coordinates; connected fields hide their manual values. Rotation fields display degrees; linked rotation vectors represent radians.

The Image Texture nodes use Flat projection and Repeat extension: X and Y of the transformed vector sample the image. UV has Z = 0, so Scale Z or Location Z alone does not change a flat image. Rotation X/Y can still change the result. Object uses the preview mesh; Blender object selection and instancing are outside this lab. The preview uses its own Y-up object axes.

Connected maps replace the corresponding manual material controls. The normal image passes through Normal Map before the shader; it changes shading rather than geometry. Disconnecting an Image Texture's Vector input uses the mesh's UVs. Disconnecting Texture Coordinate from Mapping exposes its manual Vector XYZ.

For scalar maps the browser renderer samples its standard roughness and metalness channels. Bundled roughness maps are grayscale. Arbitrary colored-image-to-value conversions may differ from Blender.

## Code Lab scope

Code Lab runs in the browser without a .NET runtime. Supported: top-level statements; `int`, `float`, `double`, `bool`, `string`, `var` and the lab types `Color` and `Direction`; arithmetic with C# integer division and `float`/`double` printing; string concatenation and `$"…{x}"` interpolation; `if`/`else`, `while`, `do`/`while`, `for`, `break`, `continue`, the conditional operator; casts between numeric types; `Console.WriteLine`/`Write`, `Math.Abs/Max/Min/Sqrt/Pow/Floor/Round`, `.ToString()`, `char`, string indexing `s[i]`, `Length`, `ToUpper/ToLower/Trim/Substring/IndexOf/Contains/Replace/StartsWith/EndsWith`, and a calculator mode for the first lessons. The checker enforces types, scopes, definite assignment and method overloads before running. Local methods (`void`/typed, parameters, `return`, call stack), arrays (`int[]`, `Color[]`, `new T[n]`, `Length`) and `foreach` are part of the later levels; classes, structs, `List<T>` and the Unity-like layer belong to Code Lab 02. The `drone` object exists only in the lab; everything else is standard C#.
